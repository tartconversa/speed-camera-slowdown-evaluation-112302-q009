# 使用说明

## 目标

运营分析需要回答三件事：

1. 在测速摄像头附近，车辆是否按预期减速，而不是因拥堵、弯道或路口自然减速？
2. 对不同道路与限速，这一行为是否一致？
3. 证据是否足以扩大启用范围，还是应继续采集、有限启用或暂缓？

## 分析口径

### 1. 先确定有效暴露

一个轨迹窗口只有同时满足下列条件才进入比较：

- 同一道路/方向/地图版本下存在 `confirmed` 且在有效期内的目录条目；
- 目录条目的方向与轨迹方向一致；
- 窗口内有 `camera_seen=yes` 的实际识别记录；
- 识别点前后都有样本，能形成前后比较。

否则窗口被标记为下列之一，并给出原因（均可在 `exposure.windows[]` 查看）：

| 状态 | 含义 |
| --- | --- |
| `no_confirmed_camera` | 该范围只有待复核/已撤回条目，或没有条目 |
| `direction_mismatch` | 同道路同版本只有对向确认条目 |
| `map_version_mismatch` | 有确认条目，但地图版本与样本不符 |
| `camera_not_observed` | 地图有条目，但窗口内车辆没有识别到 |
| `incomplete_geometry` | 缺少识别点前或后的样本 |
| `mixed_strategy_state` | 窗口内策略状态不一致 |
| `multiple_map_versions` | 窗口内地图版本不一致 |

**目录条目数量不是有效暴露数量。** 一次经过 = 一个窗口，无论该范围有几个条目。

### 2. 主指标

对每个有效窗口：

```
approach = 识别点之前最后一个有效样本的速度
zone_min = 识别点起 50 m 内的最低有效速度
slowdown = approach − zone_min
```

`slowdown > 0` 表示进入摄像头区域后减速。识别点取窗口内最早 `camera_seen=yes`
的样本偏移。

### 3. 排除项

- **交通事件窗口**（`traffic_state=incident`）不进入常态效应估计。
- **物理不合理跳变**：相邻有效样本折算加速度超过 10 m/s² 时，后一个样本被排除，
  并在 `excluded_samples` 中记录原因。事件造成的极端速度不会被平均进结论。

### 4. 何时估计效应

只有当同一范围内同时存在：

- 至少 `min_per_arm`（默认 2）个策略窗口，且
- 至少 `min_per_arm` 个未启用对照窗口，且
- 两臂的交通状态、天气、采样率、识别偏移完全相同，

才计算“策略臂减速中位数 − 对照臂减速中位数”，并用分层内重采样给出 95% 区间。
区间下界高于 0 才判定 `estimated`；否则为 `inconclusive`；缺臂或条件不齐为
`insufficient_control`。若分层内重采样完全无变异，也会降级为 `inconclusive`，
避免把零方差当成确定效应。

### 5. 不允许的推断

- 不同道路之间不互相充当对照用于启用决定；`effects.cross_scope` 与
  `effects.limits` 只是探索性敏感性分析。
- 同一范围有多个目录条目、限速不同时，不把窗口唯一归到某个限速；该范围
  `limit_kph` 为空，并在说明中标注歧义。
- 摄像头前后平均速度的差异本身不足以证明策略效果。

## 区域决定

| 决定 | 触发条件 |
| --- | --- |
| `limited`（有限启用） | 同范围效应 `estimated` 且有效窗口充足（≥ 4） |
| `continue_collect`（继续采集） | 同范围效应 `estimated` 但窗口较少；或 `inconclusive` |
| `hold`（暂缓） | 无有效窗口、缺少对照、无效应估计，或计划为 `proposed` |

同范围有正向可估计效应时，若窗口不足也会保持有限启用并继续采集，而不是
直接扩大。

建议附带 `reasons` 与 `evidence_basis`，便于运营负责人复核。`proposed` 范围
永远为 `hold`，必须先转正并重新审查。

## 地图变更与撤回流程

1. **目录更正**（方向、限速、道路层级、撤回）后，运行
   `speed-camera-eval review 旧资料 新资料`，得到：
   - `changed_windows`：哪些历史窗口的关联从可比较变为丢失（`lost`）、新增
     （`gained`）或改变（`changed`）；
   - `recheck_scopes`：哪些生效范围需要重新审查及原因；
   - `historical_windows`：需要保持原始地图版本与策略状态的行程。
2. **局部撤回**：`withdraw --road-id … --direction …` 或 `--plan-id …`
   计算影响。输出只描述操作结果，不修改输入；实际执行时以 `status=withdrawn`
   追加新版本计划，推荐同时给出新 `plan_id` 与生效日。
3. **已记录行程不重写**：速度、地图版本、策略状态保持原始值。

## 调度复核清单

- 本次分析固定到哪个快照？是否可重现？
- 每个生效范围有多少有效窗口？两臂各多少？
- 是否存在 `coverage_gaps` 中的缺口？
- 是否有目录更正导致 `recheck_scopes` 非空？
- 撤回后哪些范围仍生效？历史行程是否保留原始版本？

## 数据质量诊断

`analyze` 报告的 `data_quality.issues` 覆盖：表头/字段错误、重复主键、重复样本、
孤儿样本、窗口缺样本、窗口内地图/策略冲突、样本偏移乱序、目录或计划指向没有
轨迹的道路/方向、以及同范围重复生效计划。错误级问题会阻止 `import`；警告级
问题保留记录并在报告中列出。
